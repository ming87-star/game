# 탑 오르기

주인공이 탑을 올라갑니다. 화면 **왼쪽 · 가운데 · 오른쪽을 누르면 그 방향으로 한 칸 옮겨
가며** 위층에 오릅니다. 점프는 실패하지 않습니다 — 좌우는 난이도가 아니라
**어느 길로 갈지 고르는** 조작입니다. 무기는 자동으로 나갑니다.

빌드 도구 없이 돌아갑니다.

```
git clone https://github.com/ming87-star/game
cd game
# index.html 더블클릭  (또는)
npx serve .
```

## 직업

시작할 때 셋 중 하나를 고릅니다. 강약이 아니라 **코인을 버는 방법**이 다릅니다.

땅에 붙은 적은 위층까지 쫓아오지 못하므로 싸움은 원래 "선택"입니다. 그런데
한 번 피하기 시작하면 코인이 없어 강해지지 못하고, 약하니까 또 피하게 됩니다.
직업은 그 나선을 끊습니다.

| | 어떻게 버나 | 특징 | 유물 |
|---|---|---|---|
| **전사** | 버티고 서서 | 방어 34%로 시작. 사거리가 길어 여럿을 한 번에 벱니다 | **먼 그림자 검** — 사거리 1.9배 |
| **궁수** | 지나가며 | 처음부터 원거리. 한 발은 약하지만 아주 빠르고, 좋은 활일수록 여러 발 | **메아리 활** — 화살이 한 번 튕깁니다 |
| **도적** | 훔쳐서 | 사거리가 짧고 매우 빠름. 18% 회피, 잡지 않아도 20% 확률로 코인 절도 | **고블린의 장갑** — 훔칠 확률·액수 상승 |

유물은 **한 판에 하나**, 38~115층 사이 어딘가에 놓입니다. 짧게 끝난 판에서는
구경도 못 합니다. UP을 먹어도 사라지지 않습니다.

궁수의 화살은 표적을 **살짝** 따라갑니다(`arrowTurn`). 걸어다니는 적을
스쳐 지나가지 않을 만큼만입니다. 끝까지 쫓아가는 유도는 최고 단계 활
**용뼈 대궁**에만 붙습니다(`homing`).

## 지금 있는 것

| | |
|---|---|
| 조작 | 화면 좌·중·우 탭 = 왼쪽 한 칸 · 바로 위 · 오른쪽 한 칸 (PC는 ← ↑ → 키) |
| 전투 | 직업에 따라 근접(사거리 안 전부)이나 원거리(적 하나씩) |
| 방어구 | 받는 피해 감소. 직업별 시작값에서 최대 70% |
| 무기 | 직업마다 8단계 (전사 검 · 궁수 활 · 도적 단검) |
| 강화 | `+1` 공격력 · `×2` 공격 속도 · `방` 방어구 · `UP` 다음 무기 · `★` 유물 |
| 길 | 한 층에 최대 세 갈래. 가운데 길은 항상 있습니다 |
| 적 | 6종 — 12·25·40·55·72층에서 하나씩 풀립니다. 처음 만나면 이름이 뜹니다 |
| 적의 발 | 날것만 날아다닙니다. 나머지는 전부 발판 위를 걸어다닙니다 |
| 코인 | 적을 잡으면 떨어지고, 50층마다 상점에서 씁니다 |
| UP | 확률이 아닙니다. 50층 구간마다 지도에 정확히 하나 + 상점에 항상 하나 |
| 회복 | 확률이 체력에 따라 달라집니다. 가득이면 2%, 30%면 28% |
| 아이템 수명 | 가까이 가면 시계가 돌기 시작해 깜빡이다가 사라집니다 |
| 끝 | 체력 0에서 사망, 화면을 누르면 재시작 |

그림은 아직 없습니다. 도형을 코드로 그려서 씁니다 (`js/textures.js`).
진짜 그림이 나오면 이 파일을 걷어내고 `load.image()`로 바꾸면 됩니다.
발판 위 아이템 표시도 지금은 글자(`+1`, `×2`, `UP`)라서, 그림이 생기면
`scene-game.js`의 `makeMark()` 한 곳만 바꾸면 됩니다.

## 무엇을 고르게 만들 것인가

이 게임의 입력은 좌우 탭 하나뿐입니다. 그래서 **고를 거리가 있느냐**가 전부입니다.
지금 세 겹으로 깔려 있습니다.

**어느 길로 갈까.** 발판 위에 무엇이 있는지 올라가기 전에 보입니다.
`⚠ 3`은 적 세 마리, 나머지는 아이템입니다. 아이템은 흔하지 않습니다 —
네 층에 하나꼴이라, 만나면 그 층이 판단할 거리가 있는 층입니다.
길은 셋일 때가 절반, 둘일 때가 절반, 열에 하나는 외길입니다.

**한 번에 한 칸까지만** 옮겨 갑니다. 왼쪽 끝에 서 있으면 오른쪽 끝으로 갈 수 없습니다.
닿을 수 없는 발판은 흐리게 표시됩니다. 그래서 "지금 저 아이템을 먹으려면
두 층 전부터 그쪽으로 붙어 있어야 한다"는 계산이 생깁니다.

그래서 **가운데 길은 항상 있습니다.** 없으면 반대편 끝에 서 있던 판이
갈 곳을 잃습니다. 같은 이유로 구간마다 하나뿐인 `UP`도 가운데에 놓입니다 —
양 끝에 두면 반대편에 있던 판은 그 구간의 유일한 UP을 통째로 놓칩니다.

**멈춰 싸울까, 지나칠까.** 땅에 붙은 적은 위층까지 쫓아오지 못합니다. 발판을
안 밟으면 안 맞습니다. 대신 코인도 못 법니다 — 그러면 상점에서 살 게 없고,
무기 단계도 안 오릅니다. 근접이라 잡으려면 붙어야 하고, 붙으면 맞습니다.
방어구는 이 저울질을 감당할 수 있게 해 주는 물건입니다.

**계속 키울까, 갈아탈까.** `+1`과 `×2`는 지금 무기를 키웁니다. `UP`은 다음 단계
무기를 주지만 **쌓아둔 강화를 전부 잃습니다.** 그래서 `+12`까지 키운 강철 검을
들고 있다면 UP이 오히려 손해입니다. 언제 갈아탈지가 판단입니다.

UP은 확률로 뿌리지 않습니다. **50층 구간마다 지도에 정확히 하나**, 그리고 그 구간
끝의 **상점에 항상 하나**. 그래서 무기 단계는 운이 아니라 계획의 문제가 됩니다 —
지도에서 주울지, 코인을 아껴 상점에서 살지, 아니면 둘 다 건너뛰고 지금 무기를
계속 키울지. 대신 단계가 천천히 오릅니다. 윗단계 무기는 아주 긴 판에서만 봅니다.

`×2`를 두 번 겹쳐 `×4`를 만들면, 낮은 단계 무기로도 화력이 나옵니다.
그러면 UP이 계속 손해라서 **일부러 단계를 올리지 않는 빌드**가 성립합니다.
이건 의도한 곁길입니다. 최상위권은 아니지만 끝까지 갈 수는 있는 정도로 두었습니다.
밸런스를 만질 때 이 길이 막히지 않았는지 같이 확인해 주세요.

**적을 피할까, 잡을까.** 적은 코인을 떨굽니다. 코인은 50층 상점에서 강화가 됩니다.
안전하게 지나가면 상점에서 살 게 없습니다.

**회복은 필요할 때 나옵니다.** 체력이 가득하면 거의 안 보이고(2%), 절반 아래로
떨어지면 자주 보입니다(최대 28%). 자주 나와도 공짜는 아닙니다 — 길은 하나만
고를 수 있으니, 회복을 집으려면 그 층의 다른 길을 포기해야 합니다.

그리고 **버티는 것이 이득이 되지 않게** 해 뒀습니다. 발판 위 아이템은 주인공이
`armWithin` 층 안으로 들어오면 시계가 돌기 시작해, `blinkAt`부터 깜빡이다가
`life`에 사라집니다. 자리를 잡고 적을 잡아 모으는 것보다 빨리 오르는 편이
이득이 되게 하려는 장치입니다. 상점에 머문 시간은 세지 않습니다.

## 적이 흘러가는 방식

한 종류가 계속 같은 비율로 나오면 위층이 아래층과 똑같아 보입니다.
그래서 비중을 파도처럼 움직입니다 — 등장한 뒤 `rampFloors` 층에 걸쳐 흔해지고,
**다음 종류가 풀리면** `fadeHalfLife` 층마다 절반으로 물러납니다.

```
   층      기는 것  단단한놈    날것   빠른놈    거인    사수
    0       100%      -       -      -      -      -
   20        66%     34%      -      -      -      -
   40        32%     25%     34%     9%     -      -
   72        15%     11%     15%    21%    29%     9%
  120         7%      6%      8%    11%    15%    53%
```

`node survey.js` 위쪽 표에서 층별 적 등장 확률을, 아래 표에서 화력 대 체력을 봅니다.

## 땅과 하늘

**날것만 날아다닙니다.** 나머지는 전부 중력을 받고 발판 위를 걷습니다.
발판 끝에 닿으면 돌아서며 순찰하다가, 주인공이 **같은 발판에 올라서면**
달려듭니다. 그때는 낭떠러지를 개의치 않으므로 그대로 떨어지기도 합니다.
이걸 위해 발판마다 보이지 않는 정적 몸체를 깔아 둡니다
(`scene-game.js`의 `addFloor`). 나는 적은 그 몸체를 그냥 통과합니다.

`chaseWithin`은 좁게(0.45층) 잡아야 합니다. 한 층 아래에서부터 반응하게 두면
**주인공이 도착하기 전에 발판 밖으로 걸어 나가 떨어져 버립니다.**
그러면 잡을 적도 코인도 남지 않습니다.

땅에 붙은 적은 위층까지 못 쫓아옵니다. 그래서 **싸움이 선택**이 됩니다 —
적 발판을 피해 가면 안 맞지만 코인도 못 법니다. 코인이 없으면 상점이 비고,
상점이 비면 무기 단계가 안 오릅니다. 그게 이 게임의 가장 큰 저울질입니다.

## 밸런스 확인

### 확률부터 (`node survey.js`)

층 생성기만 수천 번 돌려 무엇이 얼마나 자주 나오는지 셉니다. 브라우저를 안 띄우니
즉시 끝납니다. `slotChance`를 만졌다면 여기부터 보세요.

한 칸 기준 확률을 적지만, 한 층에는 칸이 둘이라 실제로 마주칠 확률은 `1-(1-p)²`로
거의 두 배가 됩니다. 이걸 잊으면 "조금 올렸는데 왜 이렇게 흔해졌지"가 됩니다.

현재 기준으로 아이템이 있는 층은 약 27%입니다. UP은 확률이 아니므로 구간마다
정확히 하나인지도 함께 검사합니다.

### 그다음 실제 플레이 (`npm run playtest`)

사람처럼 고르는 가상 플레이어를 헤드리스 브라우저에 태워 올려보냅니다.
층별 체력·적 수·처치·코인·무기 상태를 찍어주고, 화면도 `shots/`에 저장합니다.
상점이 열리면 실제 버튼 좌표를 눌러서 UI가 입력을 받는지까지 확인합니다.

```
npm install
npm run playtest        # 60번 점프
node playtest.js 130 archer   # 직업을 정해서
```

회복 확률은 체력에 따라 달라지므로 `survey.js`에 체력을 넘길 수 있습니다.

```
node survey.js 400        # 체력이 가득한 상태
node survey.js 400 0.3    # 체력 30%인 상태
```

수치를 만질 때마다 서너 번 돌려 보세요. 한 번으로는 운인지 밸런스인지 구분이 안 됩니다.
현재 기준으로는 **60~160층**에서 갈립니다(한 판에 2~4분). 폭이 넓은 것은
"멈춰 싸운 판"과 "지나친 판"이 갈리기 때문입니다. 무기는 3~6단계까지,
첫 상점(50층)은 거의 매번 봅니다.

`survey.js` 끝에는 **층별 화력 대 체력 표**가 함께 나옵니다. 무기 공격력과
적 체력을 만졌다면 여기의 "한 마리 잡는 시간"을 보세요. 층이 올라가며
**서서히 늘어나야** 맞습니다. 줄어들면 위로 갈수록 전투가 싱거워지고,
가파르게 늘면 어느 층에서 벽에 부딪힙니다.

밸런스를 잡으며 걸렸던 것들 — 나중에 수치를 만질 때 같은 함정에 빠지지 않도록:

- **자동 공격은 한 번 노린 적을 끝까지 노립니다.** 매 발 가장 가까운 적으로
  갈아타면 피해가 흩어져 30마리를 쌓아두고 한 마리도 못 잡습니다.
- **`×2`에는 상한이 있습니다** (`maxMult`). 두 배가 계속 겹치면 지수로 늘어나
  40층에서 12발이 나갑니다.
- **적 공격력도 같이 올라야 합니다** (`dmgPerFloor`). 체력만 올리면
  못 죽이는데 죽지도 않는 교착이 됩니다.
- **좌우가 같으면 다시 굴리는 규칙은 아이템에만 겁니다.** 빈 칸끼리도 다시 굴리면
  "빈 칸이 남을 확률"이 사라져서, 기본 확률을 아무리 낮춰도 아이템이 넘쳐납니다.
- **길을 셋으로 늘리면 아이템이 저절로 흔해집니다.** 마주칠 확률이
  `1-(1-p)²`에서 `1-(1-p)³`으로 뜁니다. 길 수를 바꿨다면 `slotChance`도 같이 낮추세요.
- **상점은 다음 무기를 항상 팝니다.** 지도에서 구간당 하나뿐인데 상점까지 운에
  맡기면 무기 단계가 사실상 오르지 않습니다.
- **UP은 `+1`을 초기화합니다. 강화는 층수에 비례해 쌓이지 않습니다.** 실제로 들고
  있는 것은 "마지막 단계 상승 이후에 주운 것"뿐입니다 (지금은 평균 +4쯤).
  이걸 잊고 층수에 비례한다고 잡으면 주인공을 실제보다 훨씬 세게 보고
  적 체력을 과하게 올리게 됩니다.
- **적 체력도 곱으로 자라야 합니다** (`hpGrowth`). 무기 단계는 25층에 하나씩
  오르고 단계마다 화력이 약 1.8배라, 주인공 쪽은 곱으로 자랍니다.
- **상점 층은 안전지대입니다.** 적이 오지 않고, 나설 때 저절로 점프하지도 않습니다.
  "계속 오르기"를 누른 그 탭이 상점이 닫힌 뒤 게임 입력으로 한 번 더 먹히던 것을
  `tapBlockedUntil`로 막아 뒀습니다.
- **원거리는 한 번 노린 적을 끝까지 노립니다.** 매 발 갈아타면 피해가 흩어지는데,
  궁수는 멈추지 않고 지나가므로 이걸 빠뜨리면 처치가 0이 됩니다.
- **주인공은 한 층에 1초 남짓 머뭅니다.** 근접 주기(`rate`)가 느리면 몇 대 치다
  올라가 버려서 아무것도 못 잡습니다. 적 체력을 올렸다면 주기도 같이 보세요.
- **가상 플레이어는 사거리 안에 적이 남아 있으면 멈춰 싸웁니다** (`playtest.js`).
  기계적으로 계속 올라가게 두면 전투가 통째로 빠진 채 밸런스를 재게 됩니다.
- **`+1`의 값어치(`plusStep`)와 단계 간 화력 차이는 한 몸입니다.** `+1`이 너무 세면
  몇 개만 모아도 UP이 영구히 손해가 되고, 무기 8단계가 통째로 죽은 콘텐츠가 됩니다.
  지금은 `+7~13`쯤에서 뒤집히게 맞춰 뒀습니다. 그 지점이 판단이 생기는 자리입니다.

## 한 파일로 합치기

```
npm run build              # dist/index.html — 그대로 열리는 완성 파일
node build.js --fragment   # dist/artifact.html — 문서 껍데기 없는 조각
```

Phaser와 게임 코드를 전부 인라인해서 파일 하나로 만듭니다. 폰에 링크로 보내
눌러보게 하거나 정적 호스팅에 올릴 때 씁니다.
